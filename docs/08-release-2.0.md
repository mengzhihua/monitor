# Monitor 2.0.0 发布说明

本次收口服务端 `monitord` 与内嵌 Web Dashboard 的 2.0.0 版本。Agent、Hub、TSDB 和既有查询接口继续使用；新运维界面位于 Web。Flutter 客户端保持已有功能和独立版本，不把服务端压缩包描述为五端原生客户端安装包。

## 更新内容

- 运维总览集中展示主机资源、数据新鲜度、在线状态、告警覆盖和当前问题；未知、缺失、过期数据明确标注。
- 问题支持确认、备注、责任人、处理进度及最多 50 项原子批量操作；版本冲突保留草稿，写入失败不会部分成功。
- 历史检索支持分页和完整筛选结果的 JSON/CSV 导出；个人视图按认证身份保存在服务端，跨浏览器使用。
- 内置 18 组常用聚合看板，按真实采集图表匹配主机、网络、数据库、容器等场景。
- 通知诊断展示本机队列、通道接受/失败及抑制原因；计划维护支持立即/预约、全局/精确告警范围、独立取消及重启恢复。
- 修复首次通知被维护抑制或发送失败后重复提醒不再调度的问题；维护结束后按规则产生新提醒，不补发维护中的旧事件。
- 修复损坏的处置记录或个人视图文件可能被当作空库接受的问题：缺失结构、`null` 或空 JSON 对象会阻止启动，原文件保留，避免下次保存覆盖原件。
- 发布收口检查服务端与 Web 版本一致性；发布包核对真实二进制的版本、目标平台和源码提交，提供内容清单及 SHA-256。

权限、容量、身份切换及并发约束见 [运维工作台说明](06-monitor-2.0.md)，预设看板见 [聚合看板说明](07-preset-dashboards.md)。

## 从 1.x 或 2.0 开发版升级

1. 记录现有可执行文件、启动命令、私有配置路径和**实际数据目录的绝对路径**。配置和数据不在发布包内，不能用新空目录代替旧目录来验证升级。
2. 正常停止旧服务；保存旧二进制和私有配置副本。使用旧服务支持的离线备份命令备份整个数据目录（以下路径只是示例，备份目标必须不存在）：

   ```sh
   /opt/monitor-old/monitord -config /etc/monitor/monitor.yaml \
     -data-dir /var/lib/monitor -backup-dir /srv/backups/monitor-before-2.0
   ```

   旧版本没有备份命令时，停机后完整复制实际数据目录。备份包含登录密码，应按私有数据保管。服务正在运行时禁止使用文件复制制造不一致快照。
3. 解压所需系统/架构的包，先核对 SHA-256 和 `monitord -version`。macOS Universal 同时包含 Intel 与 Apple Silicon；Android arm64 包是命令行二进制，**不是 APK**。
4. 用新二进制、原配置和原数据目录启动，保留原有监听地址与服务管理方式。包内快速启动器只用于本机新建实例，监听 `127.0.0.1:20099`，不代替现有部署启动命令。
5. 登录检查历史曲线、节点、告警、个人视图、处理记录和维护计划，核对实际采样时间。必要时正常重启一次确认记录仍在。配置通知通道的生产实例会按既有规则通知，不要用生产通道作为测试接收器。

已有 token/用户/OIDC/LDAP 配置继续使用；无认证的旧部署升级后会生成 `<data_dir>/web-password` 并要求登录。保持数据目录和凭据可保留对应账号的个人视图，更换 token 会使用新的视图空间。

处理记录 v1 文件在首次成功写入时升级为 v2；合法旧数据继续可读。个人视图和维护计划使用各自版本 1 文件。持久化文件损坏时应保留原件并从已验证备份恢复，不应删除文件以绕过启动错误。

## 回退

停服务，使用升级前的二进制、配置及**升级前整目录备份**恢复到一个新目录，再把启动命令指向该目录。不要让旧版本直接写入升级后的处置文件；不要把不同时点的 TSDB、告警、账号视图、维护计划和密码拼接到一起。回退会舍弃备份时点后的新增数据和处理操作，应先另行保留当前目录。

具有备份工具的旧二进制可使用：

```sh
/opt/monitor-old/monitord -config /etc/monitor/monitor.yaml \
  -data-dir /var/lib/monitor-restored \
  -restore-from /srv/backups/monitor-before-2.0
```

## 构建与发布包

准备 README 指定的 Go/Node 工具链，工作树中的版本文件应一致。正式打包要求源码已提交、工作树干净，且二进制来自同一提交。

```sh
make all
make test
make package-server
```

输出位于 `dist/monitor-2.0.0-<提交短 SHA>/`，含 Linux amd64/arm64、macOS amd64/arm64、Windows amd64、FreeBSD amd64/arm64、Android arm64；在 macOS 上附加 Universal 包。`manifest.json` 记录目标及构建来源，`SHA256SUMS` 校验归档内容。只打包明确的二进制与文档白名单，不包含用户数据、真实配置、令牌或本机开发规则。

```sh
# macOS，在发布目录执行；Linux 可使用 sha256sum -c SHA256SUMS
shasum -a 256 -c SHA256SUMS
```

源码同步开发分支不等于创建托管平台 Release；Git 标签发布会触发仓库独立的多端 CI 流程。当前包采用 macOS ad-hoc 签名，没有 Apple Developer ID 签名和公证。

## 最终组合验收

最终版本的本地验收结果在交付前补齐，开发阶段的历史记录保留在 [运维工作台说明](06-monitor-2.0.md)。构建证据、自动化运行证据与真实设备验收分别记录，不把跨平台编译通过解释为所有平台的实际部署验证。

通知诊断只保留本进程最近 500 条结果，重启清空；通道 HTTP 2xx 表示接口接受，不证明用户收件。维护计划仅作用于当前服务端，不向远端 Agent 下发。短时 Hub 负载和持续采集测试不代表生产规模或长期稳定性承诺；告警升级值班、SLO、链路追踪等仍属于后续能力。
