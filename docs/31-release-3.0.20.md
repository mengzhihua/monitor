# 3.0.20 发布说明

本版本围绕服务运维闭环：接入检查 → 发现异常 → 服务依赖定位 → 处置 → 交接。完整行为与数据口径见 [产品质量说明](30-product-quality.md)，接口定义见 [OpenAPI](../api/openapi.yaml)。

## 使用入口

- 「接入与运行检查」按当前实例的实际接口证据检查采集、历史保存、告警求值、通知和服务配置。未知项需要继续检查，不自动标记成功。
- 「服务与拓扑」支持搜索、异常筛选、统计窗口和 CSV。管理员可以编辑关联告警与依赖，预览后保存；冲突时保留草稿供人工核对。
- 服务交接报告提供同一快照的依赖范围、当前告警、统计覆盖与处理记录，可导出 JSON 和不含脚本的可打印 HTML。报告最多包含 200 条匹配处理记录，并说明保留及截断情况。
- 刷新失败保留旧快照，明确标记时间；保存响应丢失时提示结果不确定，先刷新核对，不能据此重复提交。

## 接口兼容变化

| 场景 | 3.0.20 行为 | 调用方调整 |
| --- | --- | --- |
| 服务 / 告警历史不足 | `sla` / `uptime` 为 `null`，给出 `known_seconds` / `unknown_seconds` | 显示数据不足，不转换为 0% 或 100% |
| 服务配置保存 | `PUT /api/v1/services/config` 和原 `PUT /api/v1/services` 必须带 `revision` | 先 `GET /api/v1/services/config`，再携带返回的版本保存；缺失返回 428，冲突返回 409 |
| 配置预览 | `POST /api/v1/services/config/preview` 不持久化配置 | 可以校验拟保存树；预览成功不能代替保存 |
| 交接报告 | `GET /api/v1/services/report` 仅 troubleshooter / admin 可读 | viewer 不可导出；保留导出文件时按运维资料管理 |
| 服务工作台范围 | 服务树、告警聚合和处理历史属于当前实例 | 选择远程节点不会把这些本地数据变成远程数据；带远程 `node` 的报告请求返回 400 |

统计是基于已保留告警状态转移的“未告警占比”，不是独立业务探测。服务百分比取关联项最小值；无关联、未知、历史不足均不能证明业务 SLA 达标。

## 升级与回滚

1. 对照下载资产的版本、提交及 `SHA256SUMS` / 包内 manifest；为目标系统选择正确架构。
2. 记录现有二进制、启动参数、配置文件和数据目录位置。先停止自己的 Monitor 实例，确认进程退出，避免对正在写入的数据目录做离线备份。
3. 用现有版本执行 `monitord -config <配置路径> -data-dir <数据目录> -backup-dir <新备份目录>`。另行安全备份配置及凭据；诊断包和交接报告都不是完整备份。
4. 保留旧程序，替换程序文件并按原参数启动；不要用示例配置覆盖生产配置。检查 `/healthz`、版本信息、登录、图表、服务配置与处置历史，再验证自己的通知通道。
5. 回滚时停止新实例，恢复旧程序及原配置；使用旧版本从升级前备份恢复到一个新的数据目录：`monitord -config <原配置> -data-dir <新恢复目录> -restore-from <升级前备份>`，按该目录启动后核对。不要覆盖仍在使用的数据目录。

离线备份工具的完整约束见 [持久化与灾难恢复](08-release-2.0.md)。

## 发布验证与边界

正式 Release 在创建标签前执行完整 CI；任一必需任务失败均不能进入打包。服务端安装包只包含显式白名单中的程序、示例、操作文档及 OpenAPI，不包含本地规则、运行配置或数据。版本与源码不一致、工作区含未提交的跟踪文件时，服务器正式打包脚本会拒绝执行。

发布前本机已通过 Go 全量 race / vet、45 项前端模型测试、14 项架构规则测试、应用与 E2E 类型检查、Flutter 静态分析和 69 项测试。隔离进程验收覆盖服务编辑和交接、角色权限、配置冲突、处置记录、通知本地传输、维护窗口、告警规则、插件生命周期、SAML、崩溃恢复与离线备份。Hub 10 / 100 / 1000 个模拟节点的 HTTP 写入及重启恢复通过，不能等同于 1000 个真实 Agent 长连接。

全部浏览器用例和三种 Go 运行平台必须在该版本的 Release 验证阶段通过；各任务日志和资产以 [GitHub Actions](https://github.com/mengzhihua/monitor/actions/workflows/release.yml) 为准。浏览器手机视口、交叉编译和本机回环测试只证明各自覆盖的行为，不能替代手机真机、外部通知提供商或长期生产运行验收。30 分钟持续运行也不等于 24 小时稳定性证明。未配置签名凭据的客户端资产不具备商店签名 / 公证；iOS 无签名构建不能直接作为 App Store 安装包。

高负载 macOS 开发机在默认 1 秒采集预算下，曾观察到 `load` 模块调用 `ps` 超时并报告 `signal: killed`；失败记录保留，不计为持续运行通过。该环境后续持续运行使用显式 `global.update_every: 5`，给进程枚举留出预算。默认周期未改；部署时应根据采集耗时选择周期，并检查采集器错误及样本新鲜度。设备协议验收的整套夹具在该机耗时 89 秒，脚本总预算调整为 120 秒，单次传输超时和故障恢复断言保持不变。
