## 2026-09-23 查询和图表优化

TSDB 原始数据与降采样数据在求平均值、最值、总和和末值时，改为直接累加到目标时间格；中位数仍保留排序所需的样本列表。测试覆盖六种聚合方式、加权平均、零计数和空时间格。

同一台 Intel i7-9750H macOS 机器上，`BenchmarkQuery24Hours600Points` 每轮读取24小时历史并聚合为600点，固定30轮：改动前 `530641 ns/op、556379 B/op、1474 allocs/op`，改动后 `500466 ns/op、413614 B/op、34 allocs/op`。内存分配次数下降约97.7%，字节数下降约25.7%；两次短跑的耗时差异不作为稳定吞吐保证。

Web Dashboard 只为视口附近的图表加载历史和订阅实时数据；图表滚出视口后停止周期请求，返回视口时补读历史。周期请求按图表ID分散在30秒内；图表定义未改变时复用现有画布。桌面和手机浏览器测试验证了按需加载、滚动返回后画布复用以及原有登录、长历史、离线恢复流程。

## 2026-09-23 Flutter 图表生命周期优化

客户端将整组图表一次性创建改为按行懒加载；只为视口及滚动缓存附近的图表读取历史和订阅实时数据。30 秒列表刷新、滚动和筛选复用同一 WebSocket，通过订阅更新消息切换图表。切到其他页签、筛选无结果或选择长时间窗口时关闭不需要的实时连接；隐藏图表页同时暂停列表轮询，恢复时补读历史。断线重连补读当前图表，切换节点或时间范围后丢弃过期请求结果。

新增界面回归覆盖 390×800、1200×800 两种视口：单个分组含100张图表时初始历史请求少于20个，后续只刷新已创建的附近图表；另覆盖筛选、隐藏页签、节点切换、延迟历史响应、图表移除和断线恢复。回环 WebSocket 测试验证握手直接限定图表、空订阅不误订阅全部指标，以及连接内订阅更新。`flutter analyze`、全部21项 Flutter 测试和 macOS Debug 客户端构建通过；Android/iOS真机行为仍须设备验收。

## 2026-09-23 Flutter 图表数据正确性

将时间序列处理从界面拆到 `app/lib/state/chart_series.dart`，所有维度共用时间轴：历史空值、实时缺失维度、非有限数值和漏采周期都保留为曲线断点；最新样本缺失时图例显示 `-`，孤立有效点可见。持续不再上报的维度也随公共时间窗淘汰旧值，缓冲区维持1200个时间位置的上限。

历史返回后只合并响应时间范围之外的已接收实时样本，不复用旧聚合点，也不把历史中的空值填成旧值。切换窗口或图表定义失效后清理待合并实时数据。历史读取失败显示自动重试状态，已有数据保留，下一次成功读取清除错误提示。回归覆盖慢响应、失败后恢复、空值与孤立点、缺失维度、重复/乱序实时帧、采集周期以及不同窗口的数据隔离。

`flutter analyze` 无问题，全部31项 Flutter 测试通过，macOS Debug 客户端构建成功。本轮没有进行 Android/iOS 真机验证。

## 检查点设计及升级

旧实现每次检查点分别同步每条序列和各层未闭合桶，2000条序列在本机需要249.66秒。新实现复制一致的内存状态后释放采样锁，将原始缓冲区、各层已闭合/未闭合桶合并成一个gzip编码、SHA-256校验的`checkpoint.v1`文件；同步文件、原子替换，再同步目录。磁盘I/O期间仍可采样和查询。写满的数据块保留原有归档格式。

恢复先读取原有块，再恢复检查点并排除重复数据；检查点之后已经归档的原始样本会补入聚合层。创建于检查点之后的新序列也包含在补算中。检查点损坏会明确报错，避免无声忽略已确认数据。单个检查点的压缩前/后大小都限制为512MiB，超出或写失败会显示持久化错误，保留之前的检查点。

- 默认30秒是调度间隔，异常退出的保证只到**最后成功检查点**，不能称为30秒硬性丢失上限。
- `db.persistence`包含检查点时间、错误、耗时和文件字节数；这些字节与各层归档块字节分开统计。
- `tier0_retention_size`约束原始归档块，检查点和rollup另占磁盘；应给活跃缓冲区及备份预留空间。
- 旧版数据可直接读取；升级前仍应停服备份。**旧二进制不能读取新检查点内的未封块数据**，降级应恢复升级前的备份，不能直接使用升级后的数据目录。
- 全块归档仍采用逐序列文件，长期大规模写入、归档时延和恢复速度还须在目标存储上测量。单次小检查点结果不能外推到数百万序列。

## 复现

先安装对应Go/Node/Flutter工具链。前端必须先构建，Go才能嵌入最新资源。

```sh
make all
make test
make verify-durability
make bench
make hub-load
mkdir -p reports
python3 scripts/soak.py --seconds 600 --output reports/soak.json
cd web && npx playwright install chromium && npm run test:e2e
cd ../app && flutter analyze && flutter test
flutter test integration_test/secure_storage_test.dart -d macos
flutter build macos --debug
cd .. && make cross
```

装有Chrome时可用`MONITOR_BROWSER_CHANNEL=chrome npm run test:e2e`。浏览器测试占用`127.0.0.1:19997`，配置和数据均为临时目录，不复用已有服务；冒烟使用19998/18999。各进程测试均清理自己启动的进程。

`make acceptance`顺序运行构建、Go/Web测试、默认登录保护、强杀恢复、Hub负载、持续采集、浏览器、Flutter单测及交叉编译。`MONITOR_SOAK_SECONDS`可调整验收时长；CI另保存负载JSON与浏览器截图/失败trace。原生Keychain测试须在macOS桌面环境单独运行。集成测试会生成测试应用，完成后需重新`flutter build macos --debug`交付主程序。

72小时测试可在稳定、禁止休眠的目标机器运行：

```sh
mkdir -p reports
python3 scripts/soak.py --seconds 259200 --output reports/soak-72h.json
```

这条命令是待执行入口，**本轮没有运行满72小时**。系统Keychain/Keystore实现使用[flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage)；没有安全存储的环境只维持当前会话，绝不退回明文保存。macOS采用非共享Keychain，删除操作可重复调用；iOS Keychain能力已配置，仍须签名及真机验收。
