# 运维响应与 HTTP 探测优化

2026-09-28，本轮继续降低运维查询的重复工作，并修复 HTTP 探测连接积累和快照导出不一致。默认登录、访问角色及已有持久化格式保持兼容。

## 历史搜索

原实现对每条候选记录拼接全部字段及最多 20 条备注，再统一转小写搜索。现在先匹配操作者条件，再逐字段搜索普通关键词，首次命中即可返回；例如按主机名搜索时，无需再扫描该主机的所有备注。

含换行的关键词仍使用原字段顺序及换行拼接规则，保留跨字段搜索行为。Unicode 仍使用 `strings.ToLower`，没有扩大为其他大小写折叠规则。分页总数、游标、导出和快照失效语义不变。

本机基准使用 Go 1.27.1、Intel Core i7-9750H、darwin/amd64、`GOMAXPROCS=4`。固定 5,000 条记录，每条 20 个 2,048 字节混合大小写 ASCII 备注，分页最多返回 25 条；备注字符串在记录间共享，构造和预热不计时。每组 3 次，目标 200ms，慢用例每次只执行一次。主机其他负载未控制，以下不是生产性能保证。

| 查询 | 优化前耗时 | 优化后耗时 | 单次分配字节前 → 后 |
| --- | --- | --- | --- |
| 主机名命中 | 843–865 ms | 0.564–0.735 ms | 507.9 MB → 73.3 KB |
| 第一条备注命中 | 904–968 ms | 25.3–26.9 ms | 507.9 MB → 10.3 MB |
| 最后一条备注命中 | 1.11–1.36 s | 482–516 ms | 507.9 MB → 204.9 MB |
| 没有匹配 | 1.38–1.47 s | 559–719 ms | 507.8 MB → 204.8 MB |
| 操作者不匹配 | 13.0–16.2 ms | 0.690–1.15 ms | 16.3 MB → 5.44 KB |

分配量使用十进制单位，是每次查询累计分配字节，不是常驻内存。末备注和未命中仍需遍历全部备注，逐字段转小写使分配次数约从 30,000 增至 100,000，但总字节减少约 60%。多行关键词保留原搜索方式，不据其时长波动宣称算法收益。这是内存中历史查询基准，不包含 HTTP、磁盘和采集成本。

在 `core/` 执行以下命令可复测，优化前参考提交为 `3779e13`，需使用相同新增基准文件：

```sh
GOMAXPROCS=4 go test -p 1 ./internal/operations -run '^$' \
  -bench '^BenchmarkHistorySearchLargeNotes$' -benchmem -count=3 -benchtime=200ms
```

## 跨 Hub 告警读取

运维总览此前逐个查询其他 Hub 的节点告警；遇到多个慢节点时，每个节点的超时会累加。现在整个服务共享最多 8 个此类出站请求，每份快照的 peer 请求阶段共用 5 秒预算，包含等待并发槽位的时间。多个浏览器同时刷新也不能各自增加 8 个出站请求。

用户取消读取会中止在途请求并丢弃未启动任务。超时、失败或未读到的节点保留 `unknown` 告警覆盖状态，不当作无告警的健康节点。已有直连和单跳转发认证规则不变。非法列表长度在构建快照前拒绝，避免无效请求触发网络查询。

5 秒是 peer 阶段的预算；本机指标处理、历史读取和 JSON 编码仍另需时间，不表示整个接口严格在 5 秒内完成。

合成基准模拟 16 个节点，每个 HTTP 告警请求固定等待 5ms；不包含目录发现和完整总览处理。3 次、每次 5 个样本：旧串行算法参考耗时 90.1–131.1ms，并发实现 11.9–12.5ms。并发调度与连接增加了单次分配（约 119KB → 218KB），这一项改善的是延迟，不是分配量。

```sh
GOMAXPROCS=4 go test ./internal/api -run '^$' \
  -bench '^BenchmarkOperationsPeerFetch$' -benchmem -benchtime=5x -count=3
```

## HTTP 探测连接与失败判定

`httpcheck` 改为复用连接池。严格 TLS 验证和显式跳过验证的任务使用独立连接池，避免复用未验证的 TLS 连接。每个池最多保留 32 条空闲连接、每个目标最多 2 条，空闲 30 秒后回收；采集器停止时主动关闭空闲连接。

任务自己的请求方法、请求头、接受状态码、超时和禁止自动重定向规则继续生效。响应头是 200，但读取响应体超时或提前截断时，现在记录失败，并保留实际状态码及已读字节数。原有 1 MiB 读取上限保持不变，不检查截断窗口之外的内容。

真实 HTTP 回归验证了 10 次检查只建立 1 条连接，停止后连接关闭；这说明连接复用生效，不代表整机吞吐提升比例。

## 运维页面与导出

- 连续输入搜索文字等待 250ms 再发起请求；输入当刻取消旧请求。枚举筛选和手动刷新立即执行。
- 导出进行时禁止重复提交；文件时间、节点、问题和处理活动均取自本次导出响应。
- 改变筛选、离开运维页或登录失效时取消未完成导出，避免后台突然下载旧文件。
- 读取失败明确显示未生成文件，不再静默使用页面里的旧快照。

## 验证

新增回归覆盖 6,000 组历史搜索旧实现对照、Unicode/跨字段边界、两个浏览器请求共享并发上限、peer 超时/取消、无效参数不访问 peer，以及 HTTP 探测连接复用和响应体错误。各相关 Go 包的定向竞态检查通过。

整合验证通过：全量 Go vet 与 race、Web 类型检查/生产构建及嵌入服务端构建；运维总览、历史、批处理、个人视图和请求生命周期共 40 项桌面/移动端 E2E（新增 14 项）。最终二进制的隔离 smoke 及运维真实采样、重启持久化、历史导出和批量冲突验收通过。smoke 中出现少量采集超时日志，接口验收通过不等于全部采集器零失败。

这些测量和回归不能替代实际部署规模下的长时间采集及网络环境验证。
