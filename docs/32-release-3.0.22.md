# Monitor 3.0.22 发布说明

本版本集中修复停止和重启时可能无限等待的问题，沿用 3.0.20 的服务运维功能、配置格式和权限模型，以及 3.0.21 的发布附件校验。

## 退出行为

此前，工作线程等待 5 秒后虽然会记录超时，但后续 `Scheduler.Close()` 仍会等待未结束的采集调用。系统调用或扩展采集器不响应取消时，进程可能一直无法退出。

现在收到停止信号或开始内部重启清理后，启动独立的 30 秒退出看门狗；正常运行时间不受限制。正常清理仍依次停止工作线程、关闭采集器和数据库、释放目录锁。全部清理结束后，看门狗被回收。

如果仍未退出，日志出现 `shutdown deadline exceeded; forcing process exit`，进程以 **退出码 2** 结束。不会提前释放数据库锁，也不会与未停止的采集器共享数据目录。下一次启动走原有的异常恢复路径，恢复已落盘数据；最后一次成功持久化之后的样本可能丢失。这是故障兜底，不是正常持久化成功的证明，也不能解决操作系统整体暂停、调度停滞或磁盘故障。

内部重启如果达到此上限，同样异常退出，不再尝试原地重启；部署时由已有服务管理器的失败重启策略负责重新启动。直接在终端运行的实例需要重新启动程序。

## 升级与回滚

1. 停止旧程序，确认进程已退出，使用旧版 `-backup-dir` 创建独立备份。
2. 核对发布附件的 `SHA256SUMS.txt`，替换程序并继续使用原配置和数据目录。
3. 确认版本、登录、实时采集、服务配置及历史查询。Agent/Hub 部署同时检查远程节点权限和重连补传。
4. 如需回滚，停止新版，使用旧版程序从升级前备份恢复到新的数据目录；不要让两版同时访问同一个目录。

本次未更改数据库格式。完整服务配置迁移说明见 [3.0.20 发布说明](31-release-3.0.20.md)。

## 验收范围

新增回归用真实子进程分别模拟采集器初始化、采集和关闭阶段阻塞，并检查正常退出、超时退出码、退出日志和目录锁释放。测试使用缩短的超时以便持续运行，生产上限固定为 30 秒。发布仍经过完整 CI、跨平台构建和 16 个安装附件的完整性检查。

本机此前观察到的间歇性进程启动／采集超时尚未确定根因；本补丁只为无法完成的退出提供兜底，不将一次复测成功表述为根因修复。真实本地 Agent/Hub、升级恢复和业务流程的本次结果记录于发布验收报告。移动端真机、跨设备网络、24 小时稳定性和平台签名／公证仍需各自验证，不能由编译或回环测试替代。
