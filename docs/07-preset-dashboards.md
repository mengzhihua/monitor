# 常用聚合看板

登录 Web 看板后，点击页面上方的「常用聚合看板」。内置 26 个样板，不需要研发选择指标、编写查询或保存布局。

| 样板 | 内容 | 适用场景 |
| --- | --- | --- |
| 研发总览 | CPU、负载、内存、接口、数据库、缓存 | 日常巡检 |
| 接口与网络 | HTTP 探测、网关、网络、TCP、CPU | 接口变慢或访问失败 |
| 数据库与缓存 | 数据库、缓存、消息队列、内存、存储 | 慢查询与积压排查 |
| 容器工作台 | 容器、应用进程、宿主机 CPU 与内存 | 工作负载排查 |
| 资源瓶颈 | CPU、内存、磁盘、网络 | 主机容量与资源压力 |
| 发布观察 | 接口、进程、容器、CPU 与内存 | 发布期间人工观察趋势 |
| MySQL 排障 | MySQL、ProxySQL、磁盘、内存、CPU | 连接与查询压力 |
| PostgreSQL 排障 | PostgreSQL、PgBouncer、磁盘、内存 | 事务与连接池排查 |
| Redis 缓存 | Redis、Memcached、Pika、内存、网络 | 缓存命中与淘汰 |
| 消息队列 | RabbitMQ、Kafka、ActiveMQ、NATS 等、进程、网络、磁盘 | 消息积压 |
| Java / Tomcat | JVM、Tomcat、CPU、内存、进程 | Java 应用排查 |
| 搜索与分析 | Elasticsearch、ClickHouse、内存、磁盘、CPU | 查询与分片压力 |
| Kubernetes 工作台 | Kubernetes 组件、CPU、内存、网络 | 组件与节点巡检 |
| DNS 与连通性 | DNS 探测与解析服务、接口、网络 | 解析或访问失败 |
| 存储与磁盘健康 | 磁盘、NVMe 等设备健康、内存 | 容量与设备排查 |
| GPU 工作台 | GPU 利用率、显存、温度、CPU、内存、磁盘 | GPU 任务观察 |
| 服务存活 | 服务守护、接口探测、进程 | 服务不可用 |
| 日志管道 | Fluentd、Logstash、磁盘、内存、网络 | 日志积压与重试 |
| 值班快速巡检 | 探测、服务、容量、CPU | 交接班与故障初查 |
| 资源饱和与等待 | PSI、负载、内存、磁盘 | CPU 不高仍卡顿 |
| 容量与耗尽风险 | 空间、inode、句柄、内存 | 资源余量巡检 |
| TCP 连接排障 | TCP、conntrack、网络、探测 | 连接超时与握手失败 |
| 证书与入口巡检 | TLS 剩余天数、探测、DNS | 证书临期与入口故障 |
| 时钟同步巡检 | 系统时钟、Chrony、NTP、网络 | 时间漂移 |
| 硬件与电源巡检 | 温度、UPS、存储健康、CPU | 供电与设备异常 |
| 关键文件更新巡检 | 文件状态、修改时间、容量 | 预期文件缺失或停止更新 |

样板目录支持「通用巡检」「数据服务」「应用与中间件」「基础设施」「运维值班」分类与名称/场景搜索。每个卡片标注当前节点已采集的指标类别数量；匹配到图表不代表服务健康或数据新鲜。目录筛选独立于顶部图表筛选，不会改变正在查看的看板。没有匹配结果时可以一键清除样板筛选。

看板按当前节点实际返回的 chart context 自动匹配，缺少 context 时使用 chart ID。Hub 切换节点后跟随当前节点；顶部筛选、时间范围、实时更新和图表过期提示与原看板一致。默认每组展示优先级最高的四张图，更多实例可展开。全部指标入口保留原有分类浏览。

这些样板聚合展示已有图表，不把不同单位的数值相加，不生成业务成功率或 P95，也不自动判断发布成败。尚未采集的指标会显示缺失说明，接入数据后自动出现。看板无需配置不意味着能够跳过数据库凭据、HTTP 目标等采集前提；采集由现有采集器设置控制。

定义位于 `web/src/dashboards.ts`，展示组件为 `web/src/components/DashboardsPanel.vue`。

运维场景附三步排查建议，调研依据与能力边界见 [运维看板调研](08-operations-dashboard-research.md)。
