# 数据准确性与权限隔离更新

本轮检查修复了 Hub 房间授权、部分采样缺失、快速切换主机和模板编辑中的实际问题。保持原有服务地址、登录方式与默认密码保护，无需迁移指标库或处置记录。

## Hub 房间隔离

房间判断以管理页面保存的当前成员关系为准。配置 `web.users[].rooms` 的账号只读取可见节点的列表、上下文、跨节点聚合、Prometheus 指标、资产和运维记录；Cloud 空间、房间与节点数量也按可见范围返回。集群节点保留所属 Hub 提供的房间信息。

主机重新分配房间时会从原房间移出，整次变更保存失败则恢复原状态。同一主机不会因同时出现在多个房间而随机获得授权。旧配置中的重复归属保留给管理员检查，受限账号暂时看不到冲突主机；管理员重新分配后恢复。成员关系采用内存索引，常规权限判断不再遍历所有房间和节点。

局部基准 `go test -run '^$' -bench BenchmarkOrgMembership -benchmem ./internal/hub`（在 `core` 目录执行）覆盖不同节点规模。本轮 macOS 实测 1000 个房间、每房间 20 个节点时，单次成员关系查询约 112 ns，0 B/次、0 次分配；该基准仅测查询，不含网络、持久化和整机采集成本。

实时 WebSocket 在建立连接、切换节点和发送排队数据时检查权限。节点转入无权访问的房间后，原连接不再继续收到它的新指标或告警。广播保留共享编码，权限复核直接使用帧的节点标识，无需为每个客户端重新解析 JSON。

处置活动、历史分页和 JSON/CSV 导出使用同一授权范围。隐藏记录不计入可见总数；房间范围变化后，旧分页游标和导出快照返回 `409`，需要重新查询。受限账号不能查询已被移除且无法确定房间的远端节点历史；未限制房间的账号仍可查询完整历史。

兼容既有配置：未配置 `rooms` 或含 `"*"` 表示全局访问；本机与已知未分房间节点仍可读取。需要隔离的主机应明确分配房间，再给账号配置允许的房间 ID。房间限制不等同于完整的多租户配置管理权限；部署管理能力仍由账号角色控制。

一次性主机接入令牌属于入网凭据，读取和签发均要求管理员身份，并按允许的房间过滤或校验；只读、排障账号不能读取令牌。公开兑换入口仍要求有效的一次性令牌，重复兑换被拒绝。集群副本若缺少可确认的来源房间信息，受限账号暂时不能读取，避免被误当作共享的未分组主机。

## 当前指标与历史指标

假设上一采样是 `used=75, free=25`，本次只采集到 `free=30`：当前指标接口、Prometheus、外部导出和直接引用维度的告警表达式只使用 `free=30`，不会将旧的 `used=75` 标为新采样。缺失变量按告警引擎既有语义成为 `UNDEFINED`，下一次正常采样后恢复求值。

显式配置 `lookup` 的规则继续查询指定历史窗口，TSDB 中原有数据保留。CSV 导出使用标准转义与缓冲写入，图表或维度标识含逗号、引号、换行时仍保持正确字段边界。可能被表格软件当作公式的文本标识添加单引号保护；数值与时间仍为数值，JSON 保留原始标识。

## 模板、资产与诊断面板

- 模板规则编辑保留 `chart_labels`、规则宏、布尔值、引号和多行说明；保存成功清理已提交草稿，再次编辑使用新版本。
- 资产读取切换节点时清空旧表单并取消旧请求，加载失败不能提交上一台主机的数据。保存绑定实际加载的记录，保存期间不能切换编辑对象。
- 有效模板预览取消过期请求，清空选择同时清空结果。
- 日志、关联分析和上下文面板随主机切换重新加载；旧请求被取消。关联分析切换方法时也防止慢响应覆盖新结果。
- Cloud 中选择主机按节点 ID 导航并清空旧图表筛选，同名主机不会仅凭名称选择。

这些改动减少被放弃的请求、重复结果处理和错误节点查询；没有将局部改动外推为整机 CPU 或内存下降百分比。

## 验证入口

新增 Go 回归覆盖生产房间配置、聚合查询、Prometheus、实时流切换及撤权、处置分页与导出、缺失维度、模板 YAML 往返和 CSV 特殊字符。浏览器回归在桌面与手机视口模拟慢响应、切换节点、模板连续保存和资产读取失败。

```sh
make all
make test
python3 scripts/verify-default-auth.py
python3 scripts/verify-ai-analysis.py
python3 scripts/verify-operations.py
python3 scripts/verify-durability.py
cd web && npm run test:e2e
```

本地验证使用独立配置、测试账号和临时数据目录，不连接生产 SSH 主机，不调用用户真实 AI 服务。浏览器手机视口验证不代表所有真实手机系统的验收。

2026-10-11 本机补充运行了 `scripts/load-hub.py` 的 10 / 100 / 1000 模拟节点阶梯测试（每节点 20 维度、每维度 10 点），历史查询和重启后的副本身份均通过；这是单机 HTTP ring 摄入测试，不是 1000 台真实 Agent 的持续连接能力承诺。120 秒隔离运行测试完成 60 次查询，无采集、持久化或退出错误；当次查询中位耗时约 3.96 ms、采样最高 RSS 约 19.57 MiB。这些是当次环境的观测值，没有前后对照，不代表性能下降比例。
