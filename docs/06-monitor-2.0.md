# Monitor 2.0：运维工作台

当前交付是 **2.0.1 服务端与 Web 正式版本**，升级与验证范围见 [发布说明](08-release-2.0.md)。2.0 的重点是把现有采集、告警、历史查询组合成可操作的运维流程：发现受影响的主机 → 筛选问题 → 确认并记录处理过程 → 跳转图表调查。既有 Agent、Hub、TSDB 和 v1/v2/v3 查询协议继续使用。

## 使用

登录后默认进入「运维总览」，顶部可切换「指标图表」。`/?view=charts` 可直接进入原有图表工作区。

「指标图表 → 常用聚合看板」已整合 54 个样板，支持按场景分类、搜索、收藏及已采集覆盖数量提示。可复制和配置个人看板，恢复编辑草稿，预览并选择导入配置，查看统一历史时段及相邻时段对比，详见[聚合看板说明](07-preset-dashboards.md)与 [Web 看板更新说明](09-dashboard-final-update.md)。个人看板保存在当前浏览器，与问题中心的服务端个人视图相互独立。

- 总计包括本机、当前 Hub 已知节点，以及集群目录里只在对端出现的节点。对端节点向宣告它的 Hub 读取 `/api/v1/alarms`。这次请求不带逐跳标记，中间 Hub 可以再代理一跳；下一跳会带上标记，因此不会继续往更远的 Hub 转发。成功时覆盖范围为 `peer` 并进入问题列表。请求失败、非成功状态或没有集群时仍显示覆盖范围未知，不编造问题。已经在本地流式接入的节点继续用本地快照。
- 本机问题卡片显示该告警最近一次通知通道结果。通道接受只说明接口收下了请求，不表示有人已经阅读。对端节点没有这份本机诊断。
- CPU、内存卡片读取已有采集器的最近样本，不新增系统采样任务，也不读取整段历史。CPU 为非 idle 维度之和；内存为 used / (used + free + cached + buffers)。缺少必要维度、非有限值、尚无样本都显示「暂无数据」。
- 超过 `max(15 秒, 3 × 图表采样周期)` 的资源样本，或节点已离线/过期，显示「数据过期」，不继续展示旧百分比。卡片分别保留 CPU、内存的采样时间。
- 问题中心汇集 WARNING / CRITICAL，严重优先、待确认优先。同名告警按节点区分，不会把两台机器的确认记录混用。
- 「定位图表」切换到对应节点和图表；「查看主机」进入该主机所有图表。
- 页面前台每 15 秒刷新；后台停止轮询，未完成请求在离开页面时取消。刷新失败明确保留上次成功快照及其时间，认证失效时移除旧数据。
- 节点和问题默认各渲染前 50 条，可继续加载。个人视图每个账号最多 10 个，保存在当前服务端，连接同一服务的其他设备可读取。当前 JSON 导出包含筛选后的主机、问题及按搜索词筛选的处理历史，并标注快照时间和是否刷新失败。

## 个人视图与跨设备使用

在总览选择搜索词、节点状态、问题级别、责任人、处理进度和待确认条件，输入名称后点击「保存视图」。点击名称应用，点击对应删除按钮移除；同名保存会更新当前账号内已有视图。每个账号最多 10 个，超限拒绝，不自动挤掉旧项；名称 1–40 个字符，搜索词最多 1024 UTF-8 字节。这些视图仅保存总览筛选条件，不含处理记录查询的独立条件或实时指标。

连接**同一服务实例和数据目录**，使用同一身份登录即可读取。其他已打开页面通过「刷新视图」读取变更；不宣称在独立 Hub 之间自动复制。管理员、排障人员和只读账号均可维护自己的视图；临时分享链接、匿名 API 模式不可写入。个人视图权限不会赋予只读账号任何告警处理权限，也没有代替其他账号读取/编辑视图的接口。

身份绑定规则：

- `web.token`（含默认生成的管理员密码）与 `web.users` 各使用独立命名空间，以当前凭据的摘要识别。相同显示名称的不同凭据互相隔离；多人共用同一凭据时共用该视图空间。**更换 token/密码后进入新空间**，旧视图不自动迁移，改名而凭据不变则保留。
- OIDC 使用已验证 ID token 的 issuer + subject，不使用显示名称或短期会话 token，重新登录仍能读取。
- LDAP 使用目录 URL、UserDN 模板及精确登录名；同一配置和同一登录名重新登录保留，大小写/别名或目录配置变化会进入独立空间。未启用外部目录的统一账户 ID 查询。

旧 `localStorage` 浏览器视图在折叠区域保留，点击名称可先查看筛选条件，再逐个选择「导入账号」。不会自动上传，同名冲突不覆盖，本地原件不删除。可用不同名称保存后再导入其他视图。

服务端保存在 `<data_dir>/operations/views.json`（独立版本 1 文件），单文件最多 16 MiB、最多 1000 个身份空间，包含删除后的空空间以保持版本冲突检测。上限不足时拒绝新增，不删除其他账号数据；无自动回收。与整个数据目录一起停服务备份。Unix 写入文件权限 0600；文件中只保存身份摘要、筛选和版本，不保存认证 token。采用临时文件写入、文件同步、重命名后发布内存状态。损坏文件会使服务启动失败并保留原件，应恢复已验证的备份。

GET 返回当前账号的集合版本，POST 必须提交该版本和完整视图列表；过时版本返回 `409`。界面重新读取最新列表，保留名称与筛选草稿，核对后显式重试；不会自动重放旧提交。请求失败会显示提示，认证失效时清空已展示的账号视图。没有持久化目录的测试实例会明确提示只存内存。

## 问题确认与持久化

### 责任人和处理进度

问题中心新增三种人工处理阶段：「待处理」(`open`)、「排查中」(`investigating`)、「观察中」(`watching`)。选择新责任人或阶段后点击对应保存按钮；备注随本次操作一起写入。也可直接点击「分配给我」。确认状态、责任人和进度独立保存；更换责任人不会撤销确认，观察中不会清除严重告警或停止通知。

可指派人员来自当前服务端 `web.users` 中的管理员、排障人员，以及当前具备处理权限的登录者；配置了单一管理员密码时包括 `admin`。只读用户不可被指派。OIDC/LDAP 登录者可以分配给自己，不枚举外部目录或其他人的登录会话。名称需非空、无首尾空白和控制字符，最多 128 UTF-8 字节；使用稳定、唯一的人员名称便于追踪。已移除或改名的人员在历史中保留原名，新指派必须使用当前列表中的人员。

「责任人筛选」支持全部、分配给我、未分配、已分配；「处理进度筛选」可组合严重级别、连接状态、待确认和搜索条件使用。搜索可匹配责任人姓名。保存的个人视图包含新条件，旧视图默认全部；JSON 导出包含筛选条件、责任人、进度及历史。主机资源列表仍只应用主机搜索及连接状态筛选，最近历史只应用搜索词；概况数字始终为当前服务端全局统计。

历史记录显示责任人和进度变更前后的值。浏览器在开始编辑时记住记录版本；后台刷新不会使草稿自动覆盖他人的修改。冲突返回 `409`，界面重新读取最新记录、保留草稿，用户核对后可再次提交。确认本身不发送邮件或聊天消息。配置了 `web.ticket_webhook` 时，保存成功后会 POST 一份处理记录；对方拒绝或超时不会撤销已经保存的记录。

### 批量问题处置

管理员和排障人员可以勾选问题卡片，或点击「选择当前显示（最多 50 项）」。这里仅选择当前已显示问题的前 50 项，不自动选择所有匹配页；核对面板会列出主机、问题、级别、责任人、进度和确认状态。可逐项移除，最多 50 项。变更搜索/筛选（包括应用筛选条件不同的个人视图）时，已有选择会清空。

选择统一动作：确认、撤销确认、指派、取消指派、更新进度、添加备注。指派需选择当前可用人员，添加备注必须有内容；统一备注会写入每个问题的独立历史。提交按钮显示选中数量，旁边预览具体动作。确认与观察中均不代表告警恢复，不改变通知。

选择时固定告警阶段 ID 和处理记录版本。自动刷新或「刷新总览」不会自动推进已选版本；记录已变化/恢复时会标注并禁用提交，需重新选择并核对后再执行。后台没有加入新出现问题的行为。统一备注草稿在冲突和失败后保留，与各问题自己的备注草稿相互独立。

批量接口先核对所有告警阶段与权限，再在同一存储锁内检查所有记录版本、容量，生成一次文件替换；**全部写入成功才发布内存状态**。任一问题恢复/升级到新阶段、版本冲突或保存失败时，整批不写入。单条与批量共用保存路径，因此两种操作相遇时也有相同版本保护。健康引擎继续独立求值；检查之后进入的新阶段不会继承本批次对旧 ID 的处理。

明确收到 `409` 或 `503` 时界面提示整批未提交。若网络中断、没有收到服务端结果，则提示结果不确定并读取最新记录，需要核对后重新选择；不会自动重试或把未知结果声称为失败。服务端全局处置历史查询的旧快照只在成功保存后失效。沿用 `acknowledgements.json` 的版本 2 格式，不新增存储迁移。

### 阶段与存储

确认表示有人关注问题，**不改变健康规则求值、不抑制通知、不手动宣布恢复**。告警严重级别变化、恢复后重新触发都会产生新的阶段标识，需要重新确认。延迟提交到已经变化或恢复的问题返回 `409`。

服务整体重启后，健康引擎会重新评估并创建告警阶段；旧确认、责任人、进度和备注作为历史保留，不自动确认重启后新建的问题。升级严重级别、恢复后再次触发及重启新建的问题均从未分配、待处理开始。Hub 重启读取到相同远端阶段标识时，可继续匹配该阶段的处理记录。这避免把停机期间未观测到的变化误判为已处理。

管理员和 `troubleshooter` 可以确认、撤销确认及添加备注；`viewer` 只能阅读。操作者取自已认证身份，不能由客户端伪造。所有写请求带当前记录的 `revision`；两个人同时处理时，后到的旧版本请求返回 `409`，避免无提示覆盖备注。

责任人和进度使用同一权限规则与版本号。旧 `version: 1` 文件可直接读取，原确认、版本号和历史保留，处理进度默认为待处理。首次成功保存后文件升级为 `version: 2`；旧二进制会拒绝新格式，避免降级时静默丢失新字段。升级前先停服务并备份整个数据目录；若降级，应恢复升级前备份，不能只手改版本号。

记录保存在 `<data_dir>/operations/acknowledgements.json`，与密码、TSDB 一起纳入已有离线整目录备份。使用临时文件、同步文件内容后重命名；写入失败返回错误，不先更新内存伪装成功。记录文件损坏会阻止服务启动并报告原因，不静默丢弃操作记录。

每个阶段最多保留最近 20 条操作，最多存储 5000 个阶段，文件上限 64 MiB；达到上限拒绝新增而非自动丢弃历史。备注限制 2048 UTF-8 字节。总览 API 的 `activity` 仍返回最近 100 个阶段，独立的「处理记录查询」可分页检索全部已保存阶段，问题退出当前快照后仍可查询原记录。这不是无限保留的合规审计系统。记录需要归档时先停服务并做整目录备份，再由管理员管理该文件。

### 全部历史查询和交接导出

「处理记录查询」有独立的筛选条件，不跟随上方主机资源、问题中心或图表当前选择的节点。支持主机/问题/备注关键词、责任人完整姓名、操作者完整姓名、严重级别、处理进度、确认状态及最近 24 小时/7 天/30 天。修改条件后点击「查询历史」，不会自动把尚未提交的条件用于导出。责任人、进度、确认状态匹配阶段最终保存的值；操作者匹配任一**仍保留的操作**。时间条件按最后处理时间筛选，不是告警发生时间。

默认每页 25 个阶段，按最后处理时间倒序、同时间按阶段 ID 排序；可以继续加载更早记录。任何成功写入的处置操作或服务重启，都会使原分页游标和导出快照失效，接口返回 `409`，界面保留旧列表并提示重新查询。不会把不同快照的页拼在一起。只读用户与管理员均可查询和导出，导出权限不提供写入能力。

「导出全部匹配 JSON/CSV」覆盖上次成功查询条件下的**全部匹配阶段**，不受当前加载页数限制；服务端先校验快照，再复制一致的数据进行导出。JSON 包含筛选条件、存储数量、完整匹配记录及其保留的操作，CSV 每行一条操作，包括主机、告警、责任人、进度、时间及变更前后值。CSV 使用 UTF-8 BOM 和标准引号转义，并在以公式字符或危险前导空白开头的文本前添加单引号；JSON 原文不变。

查询结果同时显示存储用量、阶段总操作次数和历史是否裁剪。阶段超过 20 次操作后，已被裁剪的旧操作无法搜索或导出；导出不等于包含配置、认证、TSDB 的可恢复备份，也不清理服务端记录。本轮沿用现有 v2 文件格式，没有新增数据迁移。

远端告警仅代表 Hub 最近收到的状态；离线节点保留历史问题，不当作已经恢复。告警引擎未启用、暂停或尚无规则时明确提示覆盖缺口。主机连接在线也不代表所有服务正常。

未修改数据的总览与历史查询复用同一有序索引，分页只复制返回的记录及操作历史；成功保存后使索引失效，下次读取时重建；失败写入不改变快照。筛选仍计算全部匹配记录，导出范围不变。基准方法和内存边界见 [读取性能验收](05-acceptance.md#2026-09-24运维历史与总览读取优化)。

## API

| 接口 | 权限 | 内容 |
| --- | --- | --- |
| `GET /api/v1/operations` | 已认证用户 | `now`、节点资源/新鲜度、活动问题、处理记录、汇总及是否持久保存；是全局总览，不受图表 `node=` 选择影响 |
| `GET /api/v1/operations/history` | 已认证用户 | 筛选 `q`、`node`、`assignee`、`actor`、`status`、`severity`、`acknowledged`、`from`、`until`；`limit` 为 1–100，默认 25；使用返回的 `next_cursor` 继续相同条件查询 |
| `GET /api/v1/operations/history/export` | 已认证用户 | 相同筛选条件，加列表返回的 `snapshot` 和 `format=json/csv`；不接受分页游标，导出全部匹配记录 |
| `POST /api/v1/operations/acknowledgements` | admin / troubleshooter | JSON：`id`、`action`（`acknowledge` / `unacknowledge` / `comment`）、`note`、`revision` |
| `POST /api/v1/operations/handling` | admin / troubleshooter | 上述基础动作，加 `assign`（带 `assignee`）、`unassign`、`progress`（带 `status`：`open` / `investigating` / `watching`） |

总览响应新增 `current_user`、`assignees`（仅姓名/角色，无凭据）；每个处理记录含 `assignee` 和 `status`；概况新增 `unassigned`、`open`、`investigating`、`watching` 计数。指派未知人员、只读人员、无效进度或与动作不匹配的字段返回 `400`。旧确认接口继续兼容，仅接受原有三种动作。

历史响应含 `records`、`total`（匹配数）、`stored`（已存储阶段数）、`capacity`、`actions_per_record`、`snapshot`、`next_cursor`、`filter`；记录新增 `updated_at`、`history_truncated`。查询关键词最多 256 UTF-8 字节，节点 ID 最多 256 字节，责任人与操作者各最多 128 字节；起止时间为包含边界的 Unix 秒时间戳，零表示未设置边界。条件不合法或游标与条件不符返回 `400`，历史变化或重启导致快照过期返回 `409`。

错误：`400` 请求无效，`401` 未登录，`403` 权限不足，`409` 问题或记录已变化，`503` 持久保存失败。API 不允许客户端通过请求传入操作者姓名。历史记录提供最近处理上下文，不改变旧查询接口的响应结构。

### 批量处置 API

`POST /api/v1/operations/handling/batch`，仅管理员与 `troubleshooter`：

```json
{
  "action": "progress",
  "status": "watching",
  "note": "完成第一轮排查，继续观察。",
  "items": [
    {"id": "<当前问题的阶段 ID>", "revision": 2},
    {"id": "<另一个问题的阶段 ID>", "revision": 0}
  ]
}
```

`items` 为 1–50 个不重复阶段，逐项必须传 `id` 和 `revision`；服务端忽略全局图表的 `node` 选择，只处理明列的 ID。统一动作及可选 `assignee` / `status` / `note` 与单条接口一致，操作者和告警上下文由服务端取得。请求最多 16 KiB，拒绝未知字段；成功返回 `count` 和按请求顺序排列的 `records`，响应不缓存。

错误：`400` 格式/数量/重复阶段/责任人/进度无效，`401` 未登录，`403` 只读，`409` 至少一项阶段或版本已变化，`503` 容量不足或保存失败。整个批次只调用一次持久写入，不返回部分成功结果。记录上限仍为 5000 阶段，每阶段保留最近 20 次操作。

### 个人视图 API

- `GET /api/v1/operations/views`：当前账号的 `revision`、`views`、`enabled`、`persistent`、`limit` 和不含凭据的 `user`；忽略图表 `node` 选择，响应 `Cache-Control: no-store`。
- `POST /api/v1/operations/views`：`{"revision":0,"views":[{"name":"我的队列","query":"","severity":"WARNING","nodeStatus":"all","pendingOnly":true,"ownerFilter":"mine","progressFilter":"watching"}]}`。`views: []` 删除当前集合内容，版本继续增长；拒绝未知字段和客户端身份字段。错误为 `400` 格式、`401` 未登录、`403` 非账号模式、`409` 版本冲突、`422` 容量已满、`503` 保存失败。

## 通知诊断

运维总览的「通知诊断」展示**当前服务实例本机**的健康引擎；切换图表节点或问题筛选不改变诊断范围。在 Hub 上查看不会自动汇总各 Agent 的发送情况，实例名称显示在面板中。

- 展示等待发送的事件数、256 个事件的队列容量、当前正在调用的通道和开始时间；按通道类型显示配置数量、尝试/接受/失败次数及最近接受/失败时间。同类型多个配置合并统计。
- 最近 500 条**已完成结果**支持告警/图表关键词、通道和结果筛选。区分通道接受、发送失败、静默或维护抑制、无匹配通道、队列满丢弃；一次告警事件可能对应多个通道结果，使用告警事件 ID 关联。
- 统计起点为本次进程启动，不写入持久文件。超过 500 条时裁剪最旧结果，但累计数不减少；重启后清空。已有 `alarm-log.jsonl` 的 `notified` 仍表示至少一个通道成功，不能用于恢复每个通道的完整发送历史。
- 只记录进入分发流程的事件。尚未到期的延迟通知、被防抖消除的变化、初始正常/无数据状态不在结果列表中；队列中和正在调用的事件尚无完成结果。静默/维护在入队时检查，已经排队的通知仍按原有机制发送。
- 「通道接受」表示通知方法返回成功；飞书、钉钉和企业微信同时检查 HTTP 与业务码；ntfy、Gotify、Bark 检查对应的消息确认字段，其余发送器沿用自身成功条件；不代表第三方最终投递或用户收件。失败不自动重试，仍遵循已有规则的重复提醒设置。
- 错误仅返回 HTTP 状态、超时、取消、网络或一般通道错误分类。接口及分发失败日志不记录通知 URL、收件地址、令牌或响应正文，也不附带可能含敏感内容的告警说明。管理员可显式发送通道测试消息，带 `test: true` 标识并跳过静默、维护与规则路由，不修改真实告警；每 30 秒全局最多一次，不提供失败重发操作。详见[配置和测试流程](07-notification-services.md)。
- 已登录只读账号可查看。每 15 秒前台刷新；网络失败保留上次结果并明确标记，认证失效清空已读诊断。健康引擎不可用、没有配置通道、尚无结果分别显示，不作为发送成功。

`GET /api/v1/operations/notifications` 返回 `Cache-Control: no-store`，忽略图表 `node` 参数，不支持修改。主要字段：

| 字段 | 含义 |
| --- | --- |
| `available / scope / hostname / since / now / enabled / closed` | 引擎是否存在、本机范围、实例、启动/读取时间（Unix 秒）、求值开关与关闭状态 |
| `queue_size / queue_limit / in_flight` | 等待事件数量、容量、当前调用（没有时为 null） |
| `enqueued / suppressed / unrouted / dropped` | 事件级累计入队、抑制、未路由及队列满丢弃数量 |
| `accepted / failed` | 通道调用级累计成功/失败次数 |
| `channels` | 按内置类型合并的通道配置数、调用数及时间；未知自定义类型统一显示 custom |
| `recent / retention / total` | 最新结果优先的列表、保留上限、当前进程累计完成结果数 |

结果包含 `id`、`event_id`、`at`、`name`、`chart`、`severity`、`repeat`、`channel`、`outcome`、`reason`、可选 `http_status` 及 `duration_ms`（仅通道调用耗时，不包含排队等待）。`id` 只在当前进程内递增；`in_flight` 还没有结果 ID。HTTP 错误为 `http_status`，其他错误为 `timeout / canceled / network / provider_error`；抑制原因为 `maintenance / global_silence / alarm_silence / silent_recipient`。健康引擎不存在时 `available=false` 且列表为空，不从零计数推断健康状态。

## 本机配置与重启

已登录的管理员可以在 Web 顶栏「配置」，或在 Flutter 客户端查看本机且角色为 admin 时打开 Config，读取并修改**当前连接的这台 monitord** 的配置文件，然后请求重启。只读、排障和匿名身份不能读取或写入。配置里有令牌和通知密钥，接口不向其他角色返回正文。

`GET /api/v1/manage/config` 返回 `{path, yaml, writable}`。`PUT` 的正文是 `{yaml}`，最大约 1 MiB。服务端先把内容写到同目录临时文件并用配置加载器校验，通过后才以 0600 权限原子替换原文件；校验失败返回 400，原文件保持不变。空配置和未绑定配置文件不能写。`POST /api/v1/manage/restart` 在确认管理员身份后返回 202，进程先按原有路径关闭采集、健康引擎和数据库并释放数据目录锁，再重新执行当前程序。保存不会立刻改运行中的配置，重启后才会加载。这两条接口只作用于本机：带非 local 的 `node` 返回 400。Hub 上的「配置」改的是 Hub 自己的文件，不会下发到远端 Agent。原有 `GET /api/v1/agent/config` 仍是 Hub 下发给流式 Agent 的采集覆盖，不是这个文件编辑器。

## 计划维护窗口

「运维总览 → 计划维护窗口」支持为**本机**预安排变更。只有已登录的管理员能创建和取消；只读、排障账号可以查看，匿名 API 和临时分享身份不能管理。本机健康引擎未启用时明确显示不可用。Hub 上的计划只影响 Hub 自身，不会向 Agent 下发或随图表节点选择切换。

创建步骤：展开「新增维护计划」，填写标题、原因，选择指定本机告警或本机全部告警，再选立即开始或指定时间以及时长。先预览实例、范围、开始时间和原因，再确认创建。默认选择指定告警，必须明确选择已绑定的图表与告警；不支持通配符。全部告警范围包括该本机以后新建的告警。计划保存后不可原地改写，可取消后新建，保留变更痕迹。

指定时间使用浏览器时区输入和展示，服务端存储 Unix 秒；立即开始以服务端保存请求时的时间为准。可预约未来 90 天内的开始时间，API 时长为 1 秒至 7 天，界面提供 15 分钟/1 小时/4 小时/24 小时/7 天。有效区间为 `[starts_at, ends_at)`；以服务端时钟判断，无需单独定时任务或到期写盘。修改机器时钟会影响生效判断，跨时区查看显示同一个时刻。

维护只抑制**进入通知队列前**的事件。采集、告警求值、问题展示和处置记录继续运行；问题不会被标记为恢复。已经排队的通知继续按原有流程发送。多个计划按“任意匹配即抑制”生效，取消一个不会清除其他计划、全局/单条静默或配置中的周期维护。原有 `/manage/health` 的 RESET 只重置旧运行时控制，不会删除持久计划，需在本面板逐项取消。

维护结束或取消不补发旧事件。新状态变化正常通知；配置了 `repeat` 的持续告警继续按自己的周期产生新提醒，没有配置重复的告警等待下一次有效状态变化。本轮将重复周期与发送成功时间分开：首次通知被静默/维护抑制、队列满或发送失败也会推进调度周期，避免永远不再提醒或每秒失败重试；等待 `delay` 的状态不能被重复提醒提前发送，周期从延迟通知实际进入分发流程的时刻起算。`last_notified` 和日志 `notified` 仍只代表通道调用成功，不把尝试当作送达。

创建和取消前固定计划集合 `revision`。刷新不会自动更新已经预览的版本；后台有修改时禁用提交，需「读取最新列表并重新核对」。`409` 或 `503` 明确表示本次未保存；网络中断导致结果未知时阻止直接重试，先读取最新列表核对是否已创建，避免重复计划。创建草稿保留；取消需要填写原因，且不能取消已结束或已取消的计划。认证失效清空已展示列表，网络读取失败标记上次成功结果并禁止修改。

计划保存在 `<data_dir>/health/maintenance-plans.json`，独立版本 1 文件，Unix 权限 0600，最大 4 MiB。临时文件写入、同步并重命名成功后才发布给告警引擎；失败不修改生效状态。健康引擎启动时读取计划，损坏文件阻止启用该引擎的服务启动并保留原件。应随整个数据目录停服务备份；旧版二进制不理解此文件，降级后这些计划不会生效。

最多 50 个当前或待执行计划，历史与当前合计最多 200 条。创建第 201 条时仅移除最早创建的已到期或取消记录，不移除仍待执行或生效的计划；达到 50 个未结束计划时拒绝新增。列表提供当前/全部/到期/取消筛选。保存创建者、创建时间、原原因及取消人、取消时间、取消原因，不保存认证凭据。该有界记录不是完整合规审计。

### 维护计划 API

- `GET /api/v1/operations/maintenance`：已认证用户可读；返回 `available`、`can_manage`、`persistent`、`scope=local`、`hostname`、服务端 `now`、`revision`、`plans`、当前已绑定告警 `targets`、`pending_limit=50`、`history_limit=200`。计划含计算得到的 `state=active/scheduled/ended/canceled`，先列生效、再列预约、最后列历史。
- `POST /api/v1/operations/maintenance`：仅登录管理员；请求最多 8 KiB，拒绝未知字段、客户端操作者和缺失版本。支持下面的创建、取消操作，成功返回完整最新列表；操作者从认证身份读取。
- 成功响应不缓存。不接受远端 `node`，传非空且非 `local` 的节点返回 `400`，避免误将远端变更当作本机维护。`401` 未登录、`403` 权限不足/引擎不可用、`400` 参数无效、`409` 版本冲突/计划已结束、`422` 容量已满、`503` 存储失败。

```json
{
  "action": "create",
  "revision": 0,
  "plan": {
    "title": "数据库例行升级",
    "reason": "升级期间维护指定告警",
    "scope": "alarm",
    "chart": "system.ram",
    "alarm": "ram_in_use",
    "starts_at": 0,
    "duration_seconds": 3600
  }
}
```

`starts_at=0` 表示立即开始；`scope=all` 时 `chart` 和 `alarm` 必须为空。标题最多 160 UTF-8 字节、原因最多 2048 字节，不允许控制字符；单条范围精确匹配同名规则绑定的同一图表，规则删除后重建相同名称仍受该计划约束。

```json
{"action":"cancel","revision":1,"id":"<服务端计划 ID>","reason":"变更提前完成"}
```

通知诊断新增 `planned_maintenance` 抑制原因，告警的 `silenced` 读取也包含当前匹配的维护计划。诊断计数仍属于当前进程，不与持久计划历史混用。

原有告警面板区分全局和单条手动静默；解除操作后重新读取服务端实际抑制状态，不会把仍在维护中的告警显示为恢复响铃。维护与其他抑制保留提示，计划管理仍在运维总览完成。
