# Monitor 2.0：运维工作台

本轮交付是 **2.0 开发版**。2.0 的重点是把现有采集、告警、历史查询组合成可操作的运维流程：发现受影响的主机 → 筛选问题 → 确认并记录处理过程 → 跳转图表调查。既有 Agent、Hub、TSDB 和 v1/v2/v3 查询协议继续使用。

## 使用

登录后默认进入「运维总览」，顶部可切换「指标图表」。`/?view=charts` 可直接进入原有图表工作区。

「指标图表 → 常用聚合看板」已整合 18 组预设，支持按场景分类、搜索及已采集覆盖数量提示，详见[聚合看板说明](07-preset-dashboards.md)。这与问题中心的浏览器保存视图相互独立。

- 总计包括本机及当前 Hub 已知的节点。远端 Hub 只有元数据而没有本地告警快照时，显示覆盖范围未知。
- CPU、内存卡片读取已有采集器的最近样本，不新增系统采样任务，也不读取整段历史。CPU 为非 idle 维度之和；内存为 used / (used + free + cached + buffers)。缺少必要维度、非有限值、尚无样本都显示「暂无数据」。
- 超过 `max(15 秒, 3 × 图表采样周期)` 的资源样本，或节点已离线/过期，显示「数据过期」，不继续展示旧百分比。卡片分别保留 CPU、内存的采样时间。
- 问题中心汇集 WARNING / CRITICAL，严重优先、待确认优先。同名告警按节点区分，不会把两台机器的确认记录混用。
- 「定位图表」切换到对应节点和图表；「查看主机」进入该主机所有图表。
- 页面前台每 15 秒刷新；后台停止轮询，未完成请求在离开页面时取消。刷新失败明确保留上次成功快照及其时间，认证失效时移除旧数据。
- 节点和问题默认各渲染前 50 条，可继续加载。保存视图最多 10 个，只保存在当前浏览器，未做跨设备同步。当前 JSON 导出包含筛选后的主机、问题及按搜索词筛选的处理历史，并标注快照时间和是否刷新失败。

## 问题确认与持久化

确认表示有人关注问题，**不改变健康规则求值、不抑制通知、不手动宣布恢复**。告警严重级别变化、恢复后重新触发都会产生新的阶段标识，需要重新确认。延迟提交到已经变化或恢复的问题返回 `409`。

服务整体重启后，健康引擎会重新评估并创建告警阶段；旧确认和备注作为历史保留，不自动确认重启后新建的问题。Hub 重启读取到相同远端阶段标识时，可继续匹配该阶段的处理记录。这避免把停机期间未观测到的变化误判为已处理。

管理员和 `troubleshooter` 可以确认、撤销确认及添加备注；`viewer` 只能阅读。操作者取自已认证身份，不能由客户端伪造。所有写请求带当前记录的 `revision`；两个人同时处理时，后到的旧版本请求返回 `409`，避免无提示覆盖备注。

记录保存在 `<data_dir>/operations/acknowledgements.json`，与密码、TSDB 一起纳入已有离线整目录备份。使用临时文件、同步文件内容后重命名；写入失败返回错误，不先更新内存伪装成功。记录文件损坏会阻止服务启动并报告原因，不静默丢弃操作记录。

每个阶段最多保留最近 20 条操作，最多存储 5000 个阶段，文件上限 64 MiB；达到上限拒绝新增而非自动丢弃历史。备注限制 2048 UTF-8 字节。工作台展示最近处理过的 100 个阶段，问题退出当前快照后，原备注仍可从该列表查看；这不是无限保留的合规审计系统。记录需要归档时先停服务并做整目录备份，再由管理员管理该文件。

远端告警仅代表 Hub 最近收到的状态；离线节点保留历史问题，不当作已经恢复。告警引擎未启用、暂停或尚无规则时明确提示覆盖缺口。主机连接在线也不代表所有服务正常。

## API

| 接口 | 权限 | 内容 |
| --- | --- | --- |
| `GET /api/v1/operations` | 已认证用户 | `now`、节点资源/新鲜度、活动问题、处理记录、汇总及是否持久保存；是全局总览，不受图表 `node=` 选择影响 |
| `POST /api/v1/operations/acknowledgements` | admin / troubleshooter | JSON：`id`、`action`（`acknowledge` / `unacknowledge` / `comment`）、`note`、`revision` |

错误：`400` 请求无效，`401` 未登录，`403` 权限不足，`409` 问题或记录已变化，`503` 持久保存失败。API 不允许客户端通过请求传入操作者姓名。历史记录提供最近处理上下文，不改变旧查询接口的响应结构。

## 构建与验证

```bash
make all VERSION=2.0.0-dev
python3 scripts/verify-operations.py
cd core
go test -race ./internal/operations ./internal/api
cd ../web
MONITOR_E2E_PORT=20097 npm run test:e2e
```

`MONITOR_E2E_PORT` 只控制隔离浏览器测试进程的监听端口，默认仍为 19997。测试使用独立临时数据目录、专用管理员/只读测试凭据和一条静默内存规则；不会改动已有部署配置或向真实通知通道发消息。浏览器测试覆盖桌面与窄屏、真实资源数据、确认/重载、只读权限、图表跳转、保存视图、导出和刷新失败。Go 测试覆盖状态持久化、磁盘失败、并发冲突、严重级别变化/恢复/重触发、Hub 离线告警与缺失/过期指标。

正式 `v2.0.0` 标签、生产部署、各平台安装包、原生客户端界面及长时间大规模负载验收不由本轮开发版构建自动完成。正式发布时再同步版本号、发布说明及跨平台验收结果。
