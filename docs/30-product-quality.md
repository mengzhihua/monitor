# 产品质量提升与验收

本轮以现有代码的用户流程为依据，不以功能数量判断成熟度。目标是让值班人员能发现问题、理解证据、完成处置，并可靠地交接结果。

## 已落地：服务与拓扑工作台

入口：工作区「服务与拓扑」。

- 选择最近 1 小时、24 小时、7 天或 30 天，服务统计与告警统计同时切换；请求取消后不得覆盖新窗口。
- 搜索服务名、关联告警、依赖服务、图表或连接端点。异常筛选显示当前非 CLEAR 服务和窗口内曾触发的告警，拓扑只按搜索词过滤。
- 服务按严重程度优先排序；点击关联告警或依赖名称可继续检索。
- 展示服务数、异常服务数、告警统计数、连接数和上次成功时间。零结果与未配置分别解释。
- 刷新失败保留上次完整快照并标记非实时；已加载窗口和选择窗口分别保留。失败或加载中禁用导出。
- CSV 只包含当前筛选的告警统计，包括图表、未告警占比、告警秒数、窗口秒数与 UTC 时间边界。文本按电子表格公式防护规则转义。
- 窄屏沿用卡片布局，输入和操作区换行，表格转换为标注字段的卡片。

### 数据口径

统计依据服务端保留的告警状态转移历史，不是独立可用性探测。服务百分比取关联项的最小值，不是按多个告警的故障时间并集计算。当前已按告警名与图表分别计时；窗口内未保留历史、未初始化、无数据或已移除状态均记为未知秒数。只有整个窗口都有已定义状态历史时才返回百分比，否则 JSON 中 `uptime` / `sla` 为 `null`，页面显示“数据不足”，CSV 百分比留空。`known_seconds` 与 `unknown_seconds` 给出历史覆盖，不代表真实连续采集覆盖；仅有当前快照不用于追溯填满历史。历史裁剪、采集离线、没有关联告警等场景不具备完整业务 SLA 的证据。因此界面明确标注“未告警占比”，不提供业务 SLA 达标承诺。

## 统计准确性更新

- 服务状态与历史占比分开：当前已知 WARNING/CRITICAL 不因缺失历史而被隐藏；当前缺少有效状态不能显示 CLEAR。历史不完整仍可展示已知告警秒数，不将它当作完整故障总时长。
- 告警按名称引用时会包含该名称的所有当前图表实例，服务占比取最小值；任一实例历史未知时，服务占比为 null。
- API 下载和定时 CSV 与网页导出均保留未知值，并对名称/图表做公式注入防护。新增历史已知与未知秒数字段。
- 接口兼容说明：`sla` 和 `uptime` 现在允许 null。第三方消费者应区分 null 与数值 0；旧的 chart 为空的日志不能归属到具体图表，故不用于补全该实例历史。
- 保留边界：状态转移日志不能证明进程停机期间持续观测；本轮不提供业务 SLA 承诺。服务端统计当前告警快照中的实例，不是已删除告警的完整归档报表。

验证增加 `core/internal/sla/coverage_test.go`（实例隔离、未知区间、窗口边界、空窗口、无输入、共享依赖与循环）和 API CSV/服务响应断言；浏览器增加未知值不显示绿色饼图、零值正常呈现、未知区间仍进入需关注筛选及导出空值的检查。

## 服务目录编辑

在「服务与拓扑 → 配置服务树」中添加或移除服务，编辑名称、关联告警与依赖。告警和依赖列表用逗号分隔，离开输入框后解析。修改服务名称后需同步修改引用它的依赖；服务器拒绝不存在的依赖、循环、无效状态规则和超限配置。

保存前点击“校验并预览”，检查完整服务目录及移除范围，再保存。表单中的既有高级 `status_rules` 显示并完整保留；本轮表单不新增高级规则编辑器。规则可通过版本化 API 修改。离开未保存编辑时提示；保存过程中阻止模块离开。

多人编辑时不自动覆盖：服务端返回 409，页面保留草稿，点击“读取最新版本并保留草稿”后核对当前服务器配置、将移除的服务和草稿，再重新预览。此操作不会自动合并他人的字段，用户需依据最新配置修正自己的草稿。

接口：

- `GET /api/v1/services/config` 返回 `{revision, services}`。revision 为规范化服务配置的内容摘要，重启后不变。
- `POST /api/v1/services/config/preview` 接收 `{revision, services}`，校验与规范化但不写盘。
- `PUT /api/v1/services/config` 保存同一结构并返回新版本；权限仅管理员。
- 旧 `PUT /api/v1/services` 也必须携带读取到的 revision，防止旧入口绕过并发保护。缺少 revision 返回 428，过期版本返回 409，格式/规则错误返回 400。调用方需先读取配置并在冲突后重新核对。
- 状态计算规则现在经过验证、深复制和持久化，修复原来保存目录时规则被丢弃的问题。保存失败不更新内存；目录和版本读取、校验、落盘、替换在同一锁内完成。
- 本轮不改变手工拓扑写接口；服务配置版本只覆盖服务树，不覆盖拓扑。服务保存仍保留当前拓扑。

验证：目录并发写入只允许一个成功、预览不写盘、重启版本稳定、规则深复制与保留、写盘失败回滚；API 权限及 428/409；真实隔离服务的桌面/手机视口编辑、预览无副作用、冲突保留草稿、重读确认、保存生效与重新加载。

## 接入与运行检查

入口为运维总览的“接入与运行检查”按钮，或桌面管理菜单/手机“更多 → 接入检查”。页面固定检查当前连接的本机服务，不随顶部远端节点选择改变；点击本机图表会切回本机。

五步检查来自实时读取的接口，每 15 秒刷新：

1. 指标采集：图表有近期样本（不超过 max(10 秒, 三个采样周期)），且没有已启用采集器报错。图表存在但无近期样本需要检查，不会仅凭图表数量判定可用。
2. 历史保存：没有保存错误，且近期有完成的检查点（不超过 max(60 秒, 三个检查点周期)）。这仅证明最近保存成功，不代表已经验证重启恢复或备份。
3. 告警覆盖：引擎运行，至少一个活动告警，活动告警均有近期有效求值。零告警、未初始化、无数据和暂停不算受保护；绿色也不代表没有正在触发的告警。
4. 通知通道：列出已配置通道及最近接受/失败关系。只有各配置通道都有比失败更新的接受记录才显示运行证据；该状态不证明真实收件或路由。可打开现有通知诊断，由管理员明确确认发送测试；页面不会自动发送消息。
5. 业务服务（可选）：显示服务目录是否建立以及是否存在未知状态，可进入既有服务编辑流程。没有目录不影响基础采集。

局部接口读取失败时清除该来源的旧证据并显示“尚未确认”，其他读取成功的步骤仍可查看；点击重新检查可恢复。只读账号可查看状态，不显示保存配置入口；服务端继续执行原有管理权限。

这是一份运行证据清单，不是“百分百部署完成”的打勾进度。检查时间和本机范围始终显示；收件确认、业务覆盖、备份恢复及长期运行仍需现场验收。

## 请求中断与恢复

共用 HTTP 请求层现在对请求和响应体解析整体计时，避免收到响应头后正文停顿导致页面一直加载：普通读取 30 秒，保存类请求 60 秒，报表下载 120 秒。插件函数保留 70 秒传输上限，并继续遵守界面的函数执行时限；AI 分析保留 180 秒客户端上限，服务端模型调用仍有自身时限。

读取超时提示检查连接后重试；保存超时、网络中断或响应无法解析会提示“操作结果尚未确认，请先重新读取状态核对，避免重复提交”。传输层不会自动重试写操作。页面离开产生的主动取消保持原有取消语义，不转换成网络故障；计时器和取消监听器在成功、失败和取消后都会清理。

服务编辑器在不确定结果后保留草稿并取消可保存的预览，用户可重新读取服务目录确认是否已生效。下载在响应体完整收到后才交给页面，保留原有文件名和类型响应头。既有后台轮询仍按各模块原来的周期刷新，不把旧数据标为新结果。

验证包括超时中止、迟到结果、正文读取停顿、主动取消及资源清理的模型测试；浏览器用隔离服务模拟“服务器成功落盘但响应丢失”，确认草稿保留、提示结果不确定、写入仅调用一次、重读可确认已保存。

请求恢复批次验证（2026-11-18）：构建、应用/E2E 类型检查、架构及文档链接检查通过；44 项前端模型测试通过；Chrome desktop/mobile 共 44 项浏览器测试通过，覆盖请求恢复、AI 分析、插件函数、历史导出及服务编辑。隔离服务在测试后正常退出。


## 服务级交接报告

管理员或排障人员在「服务与拓扑」的具体服务卡片点击“预览 … 交接报告”。选择统计窗口后，报告汇集该服务及递归依赖的当前状态、关联告警、告警历史覆盖，以及本机的关联处理记录。查看全部内容（尤其原文备注）后，可下载 JSON 或可离线阅读、打印的 HTML；两份下载都来自同一份已预览快照，不在下载时重新查询。

范围和证据：

- 服务、告警名称与依赖来自同一份服务目录版本，报告包含配置摘要 `config_revision`。服务依赖去重，不混入其他服务。
- 处理记录按本机节点 ID/本机别名授权限定，再按关联告警名称和最后保留操作时间筛选。远端相同告警名和不关联的告警记录不导出。
- 报告保留 `captured_at` / `completed_at` 读取区间、统计起止、处理记录快照、持久化状态、存储容量及每条保留操作上限。各数据源分别读取，不宣称跨模块原子快照。
- 匹配处理记录最多导出最近 200 条，同时显示实际匹配数；单条历史已裁剪时明确标识。未知历史秒数及 null 百分比完整保留，无记录不解释为处理完成。
- 不包含认证凭据、通知配置、终端输出；备注按原文保留，分享前仍需核对敏感内容。HTML 所有文本经过转义，没有脚本和外部资源，并设置内容安全策略。

接口 `GET /api/v1/services/report?service=<名称>&window=24h` 返回 `monitor.service-handover.v1`。仅管理员/排障角色可读取，viewer 返回 403；未知服务返回 404，无效或超过 90 天的窗口返回 400；范围固定为本机，不接受远端 node。页面关闭、更换服务/窗口、身份改变会取消旧请求并清理快照。

## 模块恢复、作用域与对接契约

工作区模块下载超过 30 秒或加载失败时退出等待界面，显示刷新恢复入口；仍可切换到其他功能。恢复测试覆盖资源请求停顿、下载失败和刷新后的正常展示。

「服务与拓扑」顶部范围改为“本机 · 主机名”，与服务、拓扑和统计接口实际读取范围一致；选择远端节点不会把本机服务误标成全局或远端服务。

接入检查放在管理分组中，保留手机菜单原有的监控、诊断分析、管理顺序及键盘焦点顺序，避免新入口把管理分组挤到最前面。旧版手机统计测试同步使用“未告警占比”字段名称；不再把告警历史统计称为正常时间。

服务目录为空时，管理员得到“配置服务树”的界面操作指引，其他角色得到联系管理员的说明，避免新增编辑器后仍把用户引向手工修改配置文件。

`api/openapi.yaml` 补齐服务配置读取、预览、保存、旧入口版本要求和服务交接报告契约，明确 409/428、未知历史 null 和保留上限。同时修正原有重定向描述中的 YAML 引号，验证文件可解析且内部引用全部存在。
